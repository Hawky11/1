# Stage103 — найден отдельный нативный путь для 0x27 при ECX=0

Проверены оригинальный AALib.exe (SHA256 `28cd69a7b6219ff0fa101ecebfcbe98962dc3f391b522d1fd6e32c006cf855ba`) и существующий полный лог Stage98 r2. **37/37 проверок инструкций**, **12/12 офлайн-тестов**.

Ключевое открытие: при F7B0A значение ECX берётся из локального `[EBP-8]` — это выходной статус, формируемый F3930/F34D0/F30B0. Значение 0 для выбранного ESI=0x27 не обязательно «отказ всей функции». F7C68 содержит специальную нативную ветку: F7CC0 вызывает F2DE0 с аргументом **0**, тогда как наблюдавшийся Stage93 F7C5D вызывает тот же F2DE0 с аргументом **1**. За mode-0 веткой достижим F7DA3→CEA20. В игре это отдельно пока **не измерено**.

Лог Stage94: 201 gate, 167 type1, 34 не type1, из последних 15 с ESI=0x27 (12 producer, 3 bypass). Числа Stage102 были точны, но слово «отклонено» относится только к type1 маршруту. AI/атаки не улучшены и не подтверждены.

Полный отчёт, `results.json`, SHA-pinned `verify_stage103.py` и `test_stage103.py` находятся в архиве `ArcanaAI_Stage103_NativeStatus0_0x27_StaticAudit.zip`, предоставленном в чате. В нём НЕТ исходного бинарника или логов.
