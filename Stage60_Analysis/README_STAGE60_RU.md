# Stage60 — статический разбор происхождения координаты X

Stage60 завершает **статическую** часть исследования писателей X после подтверждённого Stage59 r2. Нового хука, DLL или настроек INI здесь нет.

## Уже сделано

- Проверен оригинальный `AALib.exe` (SHA-256 `28cd69a7b6219ff0fa101ecebfcbe98962dc3f391b522d1fd6e32c006cf855ba`).
- Подтверждены 10 рёбер прямых CALL, 5 нативных инструкций записи X и 9 участков чтения исходных значений.
- Отделён обычный расчёт перемещения (`AE6E0 -> 1E66E0`) от коррекции пары объектов (`ACDF0 -> ACB80` и `ACDF0 -> 15CEC0 -> 12D520 -> 126580`).
- Подготовлен воспроизводимый **только читающий** Python-верификатор.

## Как запустить необязательную проверку

На Windows с Python 3 используйте из корня скачанной ветки Stage60:

```powershell
py -3 .\Stage60_Analysis\tools\verify_stage60.py "D:\path\to\AALib.exe"
```

Файл `AALib.exe` должен оставаться **локальным и закрытым** — не загружайте его на GitHub. Скрипт только читает файл и печатает результаты `PASS` либо ошибку `FAIL`. Сеть, игра, администратор, MSVC и DLL ему не нужны.

## Что делать в игре

**Ничего менять не требуется.** Оставьте предыдущую рабочую Stage59 r2 DLL (**1 153 024 байта**) и исходники. Не меняйте `ArcanaAI.ini`, `Stage38CallbackWindow.inl` или `Stage59XWriterWatch.inl` ради Stage60. Дополнительный запуск COM-vs-COM для этой стадии не требуется.

## Что дальше

Stage61 следует начать со статической проверки **кто записывает исходные параметры движения** (`object+0x88`, `object+0x150`, `object+0xD4`), а также возможной связи с цепочкой формирования команд COM-ИИ. Не менять координаты или решения ИИ до подтверждения связи. Полные доказательства и границы выводов — в [STATIC_ANALYSIS.md](STATIC_ANALYSIS.md).
