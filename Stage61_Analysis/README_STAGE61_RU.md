# Stage61 — проверка «действие → движение → координата X»

Stage61 — **офлайн-анализ**. Никакой новой DLL, замены исходников, новых хуков или правок `ArcanaAI.ini` нет. Оставьте рабочую Stage59 r2 DLL размером **1 153 024 байта**.

## Зачем это нужно

Stage46 уже записывает описание действия и параметры движения, Stage47 фиксирует вызов вычисления движения, Stage59 определяет нативную запись координаты X. До сих пор эти сведения **не были объединены из одной сессии**. Новый скрипт соединяет их только при совпадении стороны, адреса объекта, идентификатора потока, указателя описания и интервалов QPC.

## Какие логи нужны

В GitHub сейчас лежат Stage46/47 от **19:56**, а Stage59 r2 от **22:07** — это **разные игровые запуски**, использовать вместе нельзя.

**Вариант A:** если на диске остались Stage46 и Stage47 от игры, запущенной **22:07 10.11.2026** (той же, что Stage59 r2), загрузите в GitHub **только эти два файла**:

- `ArcanaAI_Stage46DefinitionMotionTrace.log`
- `ArcanaAI_Stage47MotionConsumerTrace.log`

Оригинальный Stage59 r2 уже сохранён в ветке `stage59-r2-runtime-writer-attribution-evidence`.

**Вариант B:** если логи перезаписаны, не переустанавливая DLL, запустите обычный COM-vs-COM и завершите проверку после нескольких игровых действий. Загрузите **три лога одного запуска**: Stage46, Stage47 и Stage59. При новом запуске проверьте в Stage59 наличие `STAGE59_WATCH_ARMED`, `STAGE59_THREAD_INSTALLED` и `STAGE59_X_WRITE`. Если Stage46 или Stage47 не установился, не смешивайте данные разных запусков.

## Как проверить самостоятельно

Нужен Python 3 на Windows. Из папки, где сохранены три файла логов, вызовите:

```powershell
py -3 "Stage61_Analysis\tools\correlate_stage61.py" "ArcanaAI_Stage46DefinitionMotionTrace.log" "ArcanaAI_Stage47MotionConsumerTrace.log" "ArcanaAI_Stage59XWriterWatchTrace.log" --output "stage61_join.json"
```

Скрипт читает файлы и создаёт JSON-отчёт. Если объекты/потоки не совпадают или интервалы QPC несовместимы, он выводит `REJECTED` и код 2. Он **не исправляет** QPC вручную.

Проверка скрипта без игры:

```powershell
py -3 "Stage61_Analysis\tools\test_stage61.py"
```

Необязательная статическая проверка локального оригинального `AALib.exe`:

```powershell
py -3 "Stage61_Analysis\tools\verify_stage61_static.py" "D:\path\to\AALib.exe"
```

**Не загружайте `AALib.exe` в GitHub.**

## Как трактовать результат

`triple_46_47_59` — количество строго согласованных цепочек, а не число «умных решений ИИ». `triple_active_id_agrees` проверяет одинаковое значение активного ID до вызова движения. `triple_net_x_changed` означает изменение сырого X внутри Stage47. `last_59_matches_47_post_x` проверяет конечный raw X; `oldShadow` из Stage59 приблизителен.

Полное обоснование, подтверждённые x86 RVAs и ограничения — [STATIC_ANALYSIS.md](STATIC_ANALYSIS.md). Следующий Stage62 должен исследовать только полученные конкретные режимы и ID, а не начинать новые массовые трассировки.
