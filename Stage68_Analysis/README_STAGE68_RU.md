### Что доказано

**1. Запись deferred `0x25` существует, но IP записи не пойман.**

На P1, объект `2A393020`:

- Stage67 seq4412, QPC POST `1467958766094`: `O+68=FFFFFFFF`.
- Stage41 seq278, QPC PRE `1467958862984`: **уже** `O+68=00000025`, ещё до изменения pending `22→2F`.
- Значит положительная запись в `O+68` произошла **между этими снимками**. Stage65 seq276 записал запрос `2F` в другое поле и не доказан как источник отложенного `25`.
- В исходном `1E9F40` найден потребитель deferred, а не положительный writer. Конкретный нативный IP первоначальной записи **НЕ УСТАНОВЛЕН**.

**2. `O+30` включается позднее и отдельно.**

- Stage67 seq4434 POST, QPC `1467959867548`: `O+30=0`, `O+68=25`.
- Stage67 seq4436 PRE, QPC `1467959966659`: `O+30=1`, `O+68=25`.
- Seq4436 POST подтверждает перевод `O+68=FFFFFFFF`, `O+64=25`, `O+60=25`.

В оригинальном EXE обнаружен **статический кандидат writer** `AALib+1E8FEB: C6 46 30 01` (`mov byte [esi+30],1`) в обновлении объекта `1E8DC0`. Есть подтверждённый машинный `CALL` на него из объектного цикла `AE59C`; из другого цикла на тот же список идёт `AD75C→1E9F40`. Но именно исполнение `1E8FEB` в этом временном окне **ещё не наблюдалось**.

**3. Механизм общий:** на P2 Stage67 seq3465 видит deferred `26` при активации другого ID `33`. Это не уникальная особенность `25`.

### Как повторить проверку

Используя текущую ветку с нетронутыми логами и локальный оригинальный EXE:

```powershell
py -3 .\Stage68_Analysis\tools\verify_stage68.py "D:\PATH\TO\AALib.exe" --logs-root .
```

Проверка только читает файлы, сверяет SHA/оригинальные опкоды и строгие QPC-снимки. Она не утверждает, что статический кандидат исполнялся.
