# Stage69 — найден исходный нативный writer отложенного действия

**2026-11-11. Статический механизм подтверждён, выполнение writer по IP в игре ещё не перехвачено.** Исходный `AALib.exe` (SHA-256 `28cd69a7b6219ff0fa101ecebfcbe98962dc3f391b522d1fd6e32c006cf855ba`) изучен без модификаций. [Полный отчёт](STATIC_ANALYSIS.md) · [Проверка оригинального EXE](tools/verify_stage69.py).

## Что открыто

В оригинальной функции `AALib+1566B0` найден целый путь:

```asm
1566B9   mov esi,[edi]                  ; P, player
1566C2   mov eax,[esi+04]               ; O, объект действия
1566CB   mov [ebp+08],eax               ; сохранить O
          ...
156769   call AALib+0E5BF0             ; запрос немедленного действия
156770   mov eax,[edx+3F50]             ; селектор игрока
156776   mov ecx,[eax*4+06317664]       ; таблица индексов
15677D   mov edx,[ecx*4+008254E8]       ; таблица ID
156784   mov eax,[ebp+08]               ; O
156787   mov [eax+68],edx               ; записать отложенный ID
```

При исходных значениях таблиц:

| Селектор `P+3F50` | Немедленный запрос | Отложенный `O+68` |
|---:|---:|---:|
| 0 | `0x2E` | `0x24` |
| 1 | `0x2F` | `0x25` |
| 2 | `0x33` | `0x26` |

Ключевой момент: **Stage65 seq276 P1 уже наблюдал CALL с оригинального адреса `156769`, записавший запрос `2F`.** Между концом этого вызова и `156787` нет условного перехода. Следующий Stage41 PRE уже видел `O+68=25`. Таким образом, найдена конкретная оригинальная функция, в которой пара `2F/25` формируется последовательно, а не двумя необъяснимыми действиями. P2 `33/26` согласуется с другим исходным селектором.

Это **не** значит, что Stage67 записал фактическое исполнение `156787`: отдельного instruction-level наблюдателя там не было, и `P+3F50` в том запуске не снимался. Таблица индексов находится в записываемой секции `.data`; во время игры её содержимое отдельно не измерялось.

**Исправление интерпретации Stage67:** `25` уже был установлен к PRE Stage41, но это не доказывало, что он был установлен до вызова Stage65. Теперь статическая цепочка показывает, как вызов запроса `2F` может непосредственно предшествовать записи отложенного `25` в рамках одного callback.

`O+30` остаётся отдельным более поздним этапом: writer `AALib+1E8FEB` статически найден, но ещё не пойман в исполнении. Перенос `O+68→O+64` уже доказан Stage67.
