# Stage70 — пассивное подтверждение источника O+68

**2026-11-11. SOURCE ONLY.** Ветка: [stage70-native-deferred-writer-probe](https://github.com/Hawky11/1/tree/stage70-native-deferred-writer-probe). Нативная инструкция и её границы проверены по оригинальному \`AALib.exe\`; **новая DLL ещё не собрана, в игре не проверялась**.

## Что добавлено

В оригинальном EXE найден путь, где один callback делает запрос немедленного ID, затем отдельно пишет отложенный ID:

\`\`\`asm
156769   call 0E5BF0                ; немедленный запрос; Stage65 видел этот callsite
15677D   mov edx,[ecx*4+008254E8] ; отложенный ID
156784   mov eax,[ebp+08]         ; объект O
156787   mov [eax+68],edx         ; отложенный ID O+68
15678A   mov ecx,[edi]            ; продолжение
\`\`\`

Для Stage70 добавлен точечный наблюдатель по оригинальным **шести байтам** \`156784..156789\`. Вместо них ставится JMP+NOP. Обёртка снимает PRE, выполняет **обе исходные инструкции ровно один раз**, снимает POST, продолжает с \`15678A\`. Исходное значение EDX, ID, координаты, ветки решений и поведение COM не меняются. Обёртка сохраняет GPR, EFLAGS, FPU и XMM/MXCSR; **DR0/DR1 Stage59 не задействуются**.

Новый лог: \`ArcanaAI_Stage70DeferredWriterTrace.log\`. На каждой записи будет player P, object O, side, TID, QPC, originalStoreRVA=156787, EDX, значения \`O+68\` и \`P+3F50\` до/после, указатель \`P+4\` и маски чтения. После перехвата процессор исполняет MOV внутри DLL, а не по оригинальному EIP: указанный RVA — адрес исходной инструкции, а не замеренный EIP.

## Установка поверх текущей Stage67

Сначала сохрани **резервную копию рабочей Stage67 DLL (1 887 232 байта)** и исходников. Stage65 (1 879 552) и Stage59 r2 (1 153 024) оставить для отката.

В \`D:\INCUBATOR\ArcanaAIOverhaul\src\`:

1. **Добавить** [Stage70DeferredWriter.inl](../Stage70_Overlay/src/Stage70DeferredWriter.inl).
2. **Заменить** [Stage38CallbackWindow.inl](../Stage70_Overlay/src/Stage38CallbackWindow.inl) новым вариантом Stage70.

Это **overlay**, а не отдельный готовый проект. Остальные текущие файлы Stage67, \`Build.bat\`, настройки \`ArcanaAI.ini\` и оригинальный EXE не менять.

## До запуска игры

Сначала выполнить из корня клона соответствующей ветки:

\`\`\`powershell
py -3 .\Stage70_Analysis\tools\verify_stage70.py "D:\PATH\TO\AALib.exe"
py -3 .\Stage70_Analysis\tools\test_stage70.py
\`\`\`

Проверить успешный результат. Верификатор проверяет SHA-256 оригинального EXE, 27 оригинальных мест Stage69, три диапазона байтов Stage70, исходные перемещённые инструкции, защиту от конфликта DR0/DR1 и интеграцию со Stage67/59. Отдельные тесты коррелятора используют синтетические события. **Эти проверки не заменяют компиляцию MSVC x86 и дифференциальный тест машинной обёртки. Последний в текущем этапе не выполнен.** Поэтому использовать тестовую DLL в игре только после успешной сборки и оценки риска; при сомнениях оставить рабочую Stage67.

Запустить существующий \`Build.bat\` для x86. Если \`BUILD SUCCEEDED\` нет — не копировать DLL в игру. Если установка хука сообщает ERROR, не считать этот запуск подтверждением и восстановить DLL из резервной копии.

## После безопасной сборки и теста COM-vs-COM

Перед новым запуском архивировать старые логи; новый короткий бой COM-vs-COM; после боя оставить время на запись буферов (не менее 2 секунд). Ожидаются:

- \`STAGE70_DEFERRED_BUILD=2026-11-11-r1\`
- \`STAGE70_INSTALLED 1/1\`
- \`STAGE70_DEFERRED_WRITE\` с масками \`07/07\`, post-value равным EDX и корректным объектом P1/P2
- \`STAGE70_HEALTH\` с нулём в \`dropped, overflow, mismatch, readFail\`.

Для следующего анализа залей **6 файлов одного запуска**: \`Build.log\`, \`ArcanaAI_Stage70DeferredWriterTrace.log\`, \`ArcanaAI_Stage65RequestOriginTrace.log\`, \`ArcanaAI_Stage41ObjectCommitTrace.log\`, \`ArcanaAI_Stage67NativePathsTrace.log\`, \`ArcanaAI_Stage59XWriterWatchTrace.log\`. Stage40/42 можно добавить, если наблюдается интересный случай активации, но первому анализатору они не обязательны.

Локально соединить цепочку:

\`\`\`powershell

\`\`\`
