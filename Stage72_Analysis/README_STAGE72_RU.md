## Новое: откуда запускается callback 1566B0

В оригинальной функции \`158570\` значение \`0x22\` берётся из подготовленного контекста callback (\`[frame+0C]\`). Этот параметр прежде скопирован из поля игрока \`P+3ED4\` функцией \`156C00\`.

Оригинальная jump table \`00558DC4\` содержит запись:

\`\`\`text
index = 0x22
table[0x22] = 00558CE0
AALib+158CE1 CALL AALib+156A60
\`\`\`

Функция \`156A60\` может назначить callback \`1566B0\`:

\`\`\`asm
AALib+156B82  push -1
AALib+156B84  push AALib+1566B0
AALib+156BCE  call AALib+0F7E70
\`\`\`

**Уточнение:** \`0F7E70\` не запускает callback. Она записывает два DWORD в структуру: \`P+3ED0 = callback\` и \`P+3ED4 = параметр\`. Реальное исполнение позже происходит через оригинальную \`EE7BE CALL EDI\`, после загрузки EDI из \`P+3ED0\`.

Это подтверждено исходными машинными инструкциями и 23 опкодными диапазонами.

## Два разных значения — НЕ путать

В Stage71 была найдена запись \`P+3F50=1\` и формирование события с кодом **\`0x21\`**. Оригинальная \`0F2DE0\` записывает это событие в отдельную структуру по \`P+3A2C\`: код в \`P+3A30\`, режим в \`P+3A2E\` (если состояние структуры допускает запись).

В Stage72 обнаружен **\`0x22\`**, но это совсем другое поле — **аргумент callback \`P+3ED4\`**. Несмотря на соседние числа, \`0x21\` и \`0x22\` нельзя считать одной причинно связанной последовательностью без дальнейших доказательств.

## Что пока не закрыто

Stage38 не снимал \`P+3F50\` и \`P+3F54\`. Stage70 показал селектор 1 в момент **чтения**, но адрес инструкции, **записавшей 1 ранее**, по-прежнему неизвестен.

Функция \`156A60\` выбирает \`1566B0\` по собственным проверкам состояния и флагов. В игровой записи виден итог — назначение callback, — но не точный EIP внутренней условной ветки. Значение селектора могло быть установлено \`155D29\` либо одним из других нативных writer из Stage71.

**Stage73:** если цель — именно первый выбор \`P+3F50=1\`, сначала проверить владельцев аппаратных breakpoint и уже существующие точки сбора. Нельзя безопасно назначать DR0/DR1, занятые Stage59. Пассивный снимок поля на границах callback может сузить временное окно, но не докажет writer IP; точное доказательство требует отдельного безопасного source-site наблюдателя. Подменять селектор или ID нельзя.
