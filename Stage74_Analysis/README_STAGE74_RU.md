# Stage74 — снимки селектора на границах существующего callback

**Статус: исходники готовы, сборка и проверка в игре ещё не выполнены.**

Вместо нового аппаратного breakpoint расширен уже существующий Stage38. Это безопаснее с точки зрения владения отладочными регистрами: Stage59 уже занимает DR0/DR1, а свободность DR2/DR3 не гарантирована.

## Что изменено

Подготовлен **один** файл: [Stage38CallbackWindow.inl](../Stage74_Overlay/src/Stage38CallbackWindow.inl), скопированный строго из рабочего исходника Stage70 r2. В нём только четыре небольшие правки; полный исходный код сохранён.

Теперь в каждой строке `STAGE38_CALLBACK_WINDOW` в дополнение к существующим `f0..f29` должны появиться:

- `f30` — селектор **`P+3F50`**, до и после callback.
- `f31` — сопутствующее состояние **`P+3F54`**, до и после callback.

Снимок читает именно поля **игрока P**, не объекта O. Учтены маски чтения битов 30/31, прежние индексы полей, обработка отсутствующего объекта и старые Stage38/39 структуры. Новых hook-сайтов и обращений к DR не добавлено.

## Установка

1. Сохрани рабочую DLL Stage70 r2 (**1 892 864 байта**) и текущий `D:\INCUBATOR\ArcanaAIOverhaul\src\Stage38CallbackWindow.inl` для отката.
2. Замени **только** `D:\INCUBATOR\ArcanaAIOverhaul\src\Stage38CallbackWindow.inl` файлом [Stage74_Overlay/src/Stage38CallbackWindow.inl](../Stage74_Overlay/src/Stage38CallbackWindow.inl). Остальные Stage70 r2 исходники и `ArcanaAI.ini` не менять.
3. При необходимости проверь исходник:
   ```powershell
   py -3 .\Stage74_Analysis\tools\verify_stage74.py --exe "D:\PATH\TO\AALib.exe"
   ```
4. Собери `Build.bat`, проверь **BUILD SUCCEEDED**. Затем обычный COM-vs-COM тест. Старую DLL не удалять.

## Что прислать после одного теста

`Build.log`, `ArcanaAI_Stage38CallbackWindowTrace.log`, `ArcanaAI_Stage65RequestOriginTrace.log`, `ArcanaAI_Stage70DeferredWriterTrace.log`, `ArcanaAI_Stage59XWriterWatchTrace.log`. Эти логи должны быть **из одного запуска**. Если сборка неудачна, достаточно `Build.log`, в случае вылета — логов, успевших записаться.

## Какой ответ даст Stage74

- `f30: 00000000→00000001` **в одной строке** при валидных битах маски — значение изменилось **во время данного callback**.
- Если предыдущий callback закончил с 0, а следующий начал с 1, изменение произошло **между** снимками, внутри какого именно участка пока неизвестно.
- Если всё время видно 1→1, источник записи всё ещё не доказан.

**Ограничение:** Stage74 не определяет точный EIP инструкции записи; только ограничивает временное окно. Статус `SOURCE READY`, не `BUILD VERIFIED` и не `RUNTIME VERIFIED`. Никакого изменения поведения COM, координат или действий нет.
